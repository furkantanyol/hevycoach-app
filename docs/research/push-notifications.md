# Push notifications on Expo SDK 57, iOS dev build (researched 2026-09-10, cited from docs.expo.dev v57 + expo repo sdk-57)

- Packages: `npx expo install expo-notifications expo-constants` (expo-notifications ~57.0.17). expo-device NOT needed; projectId comes from Constants.expoConfig.extra.eas.projectId (1781384f-bb50-4df2-8519-26f74a7cfe41).
- app.json: `"plugins": ["expo-notifications"]`. The plugin sets `aps-environment=development` in entitlements unconditionally (withNotificationsIOS.ts). EAS Build syncs the Push capability + regenerates the provisioning profile automatically (build-reference/ios-capabilities). Do not set EXPO_NO_CAPABILITY_SYNC.
- Dev build = sandbox APNs; Expo's push service picks the environment per token.
- Credentials: `eas build --local` downloads managed credentials like a cloud build (needs `eas login`). FIRST push-capable build prompts: Apple ID login + 2FA, "Setup Push Notifications for your project" -> yes, "Generating a new Apple Push Notifications service key" -> yes. Reused afterwards. Pre-stage alternative: `eas credentials` -> iOS -> Push Notifications key. Device UDID must already be in the dev profile (`eas device:create`).
- App code: `Notifications.setNotificationHandler({handleNotification: async () => ({shouldShowBanner: true, shouldShowList: true, shouldPlaySound: true, shouldSetBadge: false})})` at module top; request permission; `getExpoPushTokenAsync({projectId})`; re-send token to server on every launch. Tap handling in app/_layout.tsx: `Notifications.getLastNotificationResponse()` (cold) + `addNotificationResponseReceivedListener` (warm), route via `router.push(data.url)`.
- Server: `expo-server-sdk` 7.2.0 (npm name; repo is expo-server-sdk-node). `new Expo()`; `Expo.isExpoPushToken`; `chunkPushNotifications`; `sendPushNotificationsAsync`. Push API needs no auth unless "Enhanced Security" is toggled on expo.dev (do not toggle before the demo). Receipts via getPushNotificationReceiptsAsync ~15 min later; DeviceNotRegistered -> drop token.
- Pitfalls: "no valid aps-environment entitlement" = capability not synced / rebuild needed after adding the plugin; token changes on reinstall; foreground notifications need the handler; Expo Go cannot do remote push (SDK 53+).
- Demo-day risk: do the first push-capable build TONIGHT (Apple-side propagation); `eas-cli@latest` is 24.0.0; local build needs network + Xcode/fastlane/CocoaPods working; a 200 ticket is not delivery, watch the device.
